## 1. 项目目标与范围

根据成分证券实际权重汇总盈利收益率，再取倒数，计算并展示纳指100滚动市盈率和前瞻市盈率。用户能够查看整体估值、行业差异及成分证券贡献，并追溯数据来源、时间与计算口径。

已确定：标的为纳指100；采用参考文章的权重加总盈利收益率算法；交付看板及需求说明书。

使用场景已确定为个人研究、本地开发测试，并部署可公开访问的网站（优先考虑Vercel）。采用中文响应式网页，按美股交易日收盘后更新。保留标准文件导入与结果导出。数据采购预算严格为零，仅使用免费可获取数据和开源采集工具，不使用付费订阅、付费试用到期续费或自动付费降级方案。

首版不包括交易执行、买卖信号、其他指数、会员收费及无可靠历史数据支撑的十年估值百分位。截图数字仅为历史转录，不作为生产数据或验收真值。

## 2. 方案比较与建议

| 方案 | 优点 | 限制 |
|---|---|---|
| 仅文件导入计算 | 易复核、供应商依赖少 | 需人工更新 |
| 每日数据接入＋文件导入 | 兼顾持续更新和复核，建议采用 | 需验证数据覆盖、授权和口径 |

## 3. 计算规则

### 3.1 基本定义

对证券 i，权重为 w_i，滚动盈利收益率为 y_i,T，前瞻盈利收益率为 y_i,F。

- Y_T = Σ(w_i × y_i,T)
- Y_F = Σ(w_i × y_i,F)
- PE_T = 1 / Y_T
- PE_F = 1 / Y_F
- 当个股PE有效且非零时，y_i = 1 / PE_i。
- 具备匹配的利润与市值时，y_i = E_i / M_i；或使用匹配口径的每股盈利与股价。

权重使用小数，目标合计为1。禁止按权重直接算术平均PE，禁止用所有公司的利润之和除以市值之和替代本算法，除非已证明其与所用权重等价。

### 3.2 盈利口径

首版决定采用以下口径：

- 滚动：TTM已报告盈利，目标为归属于普通股股东的GAAP盈利。优先使用可验证的TTM稀释EPS除以同一收盘价；或使用口径匹配的利润/市值。不同计算路径须记录并验证一致性，不能认为两者天然完全相等。
- 前瞻：FY1（下一财年）分析师一致预期EPS均值除以同一收盘价。每只证券保存预测财年结束日；不同公司财年可不同，页面明确这是FY1组合，不是共同未来十二个月组合。
- 前瞻会计口径目标为normalized（调整后）一致预期，贴近截图的分析师预测使用方式；必须验证来源元数据。不得将Yahoo默认值无证据地认定为GAAP或normalized。口径未知的记录单独标识，不纳入声称统一会计口径的完整指标。
- FY1必须由明确预测期间取得；不能仅凭名称为forwardPE或forwardEps就认定为FY1。缺失FY1时不以NTM、当年预测或历史盈利替代。
- 本项目不声称还原截图未披露的预测供应商、期限或会计口径。

滚动GAAP与前瞻normalized不是同口径盈利，因此默认不展示“盈利增速60%”或类似增长结论。可展示明确标注“不同盈利口径下的估值差异”的PE变化；两者的期间与会计口径始终可见。

### 3.3 异常及完整性

- 亏损证券保留负盈利收益率，不剔除、不归零。
- 盈利明确为零且市值有效时，收益率为零；PE展示“无意义”。供应商PE为0或空值不能据此推断盈利为零。
- 缺失值与零值分开；不可将缺失值填零。
- 全部成分和权重已知且对应盈利全部有效时，才发布完整组合指标。滚动与前瞻分别判断完整性。
- 数据不完整时展示覆盖权重、缺失列表及已知部分贡献；完整PE留空，不将覆盖部分重新归一化后冒充全指数。
- Y≤0时保留收益率，组合PE展示“无意义”，不作为低估值排序对象。
- 仅允许对已知完整成分集合的权重舍入误差归一化；建议容差为绝对值0.0001，超过即阻止发布。保存原权重、归一化系数和调整后权重。
- 公司存在多个股类时，按证券分别持有权重；收益率的分子分母须采用一致的公司或股类口径。不得用完整公司利润除以单个股类市值。展示公司总市值汇总时按发行人去重。

### 3.4 派生指标

在Y_T>0、Y_F>0时计算以下候选指标；“盈利相对变化”仅在会计口径可比时发布，默认GAAP/normalized模式隐藏；PE变化如发布必须标记为跨口径比较：

- 前瞻盈利相对变化 = Y_F / Y_T − 1。
- PE相对变化 = PE_F / PE_T − 1。
- 每投入100元对应盈利 = 100 × Y。

上述比较固定同一价格、权重快照，描述盈利估计差异，不表述为未来价格涨跌或投资回报预测。使用未舍入数据计算，最终展示才舍入。

行业权重 W_s = Σ行业内w_i；行业收益率 Y_s = Σ行业内(w_i×y_i)/W_s；行业PE = 1/Y_s。行业对整体盈利收益率的贡献为Σ行业内(w_i×y_i)，与行业自身收益率分别展示。无法分类的证券保留为“未分类”。

## 4. 数据需求与可追溯性

每个快照须包含：快照ID、方法版本、成分生效日期、权重日期、价格日期、数据截点、采集时间、运行时间、来源及原始数据标识。

证券级字段至少包括：稳定证券ID、发行人ID、代码、名称、行业、权重、价格及币种、收益率或其计算输入、盈利口径、盈利覆盖期间、预测期限、预测更新时间、有效性状态和缺失原因。

- 不固定证券数量为100或截图中的102；由有效成分名单决定。
- 全市场值与股类市值必须区分；市值汇总不能简单相加重复发行人的公司市值。
- 股价、EPS及拆股调整须一致；利润与市值币种一致。
- 主指标要求权重与价格均对应目标交易日D收盘。若仅有D−1交易日完整权重，可单独发布“滞后一交易日权重估算”，不作为同日完整主指标；遇成分调整或公司行动则禁止该估算。更旧权重不计算当日指标。
- 历史记录仅使用当时已知数据；预测修订不能覆盖旧快照。更正生成新版本并保留原版本。
- 数据来源须验证成分覆盖、负盈利处理、前瞻期限、使用授权及更新频率；不假设免费来源一定提供完整数据。

页面顺序固定为：页头与快照信息 → 数据状态提示 → 六张概览卡片 → 100元解释及口径差异 → 行业权重与估值 → 成分证券明细 → 历史快照 → 方法与来源。日期选择同步更新全部模块，不能混用不同快照。

### 5.2 页头与概览卡片

- UI-01：标题区显示权重模式；使用代理时采用第9.2节规定的完整名称。演示模式标签常驻，不能只放在页脚。
- UI-02：价格日期、权重日期和成功更新时间直接可见；运行详情可展开查看采集时间、最近失败和预测时间状态。所有时间注明时区，交易日期按纽约时间解释。
- UI-03：采用截图中的两列三行卡片顺序，TTM始终在左，FY1始终在右；极窄屏依第5.7节顺序折叠。PE与收益率为主要信息，数量和市值为辅助信息。
- UI-04：卡片由名称、数值、单位和口径/状态组成。PE显示两位小数及“倍”，收益率显示两位百分数，权重显示两位百分数；详情与导出保留计算精度，极小非零值不能直接显示为0.00%。市值注明美元及换算单位，不满足去重与覆盖要求时显示不可用。
- UI-05：滚动和前瞻各显示有效权重覆盖率。缺失显示“—”及原因，盈利非正导致PE无意义时显示“N/M（盈利非正）”；负个股PE保留负号并标“亏损”，不得使用低估值绿色。
- UI-06：100元解释紧邻卡片，按各自有效收益率生成；数据不足时不生成对应句子。默认不展示盈利增速；跨口径PE变化如展示，文字说明须与数值同处可见，不能仅依赖悬浮提示。

### 5.3 行业权重与估值

- UI-07：按行业权重降序排列，显示行业名称、权重条形图、TTM PE、FY1 PE及整体收益率贡献；行业权重条统一以0%—100%为标尺。
- UI-08：桌面使用对齐的对照表，手机按行业纵向排列，保证两个PE及其口径可同时阅读。行业可点击筛选下方成分表，筛选状态和清除入口可见。
- UI-09：行业缺失数据时遵守组合完整性规则，不以部分贡献计算“完整行业PE”；未分类单列。亏损、缺失、正常状态须使用文字或图标辅助区分。

### 5.4 成分证券明细

- UI-10：主表列顺序为序号、公司名称/代码、权重、滚动PE、前瞻PE、滚动收益率贡献、前瞻收益率贡献、数据状态。贡献以百分点展示并说明其加总关系；来源、盈利输入、财年结束日和时间戳在展开行或详情面板展示。
- UI-11：默认权重降序；支持名称/代码搜索、行业及数据状态筛选，数值列支持升降序。缺失值始终置底，排序方向可见；筛选仅改变明细展示，不重算页头的全组合指标。
- UI-12：显示“筛选后数量 / 总证券数量”，支持清除筛选。默认可浏览全部成分，不仅显示前十大；允许分页，但不能隐藏总数量或造成遗漏。
- UI-13：表头在表格滚动区域内保持可见。手机表格可横向滚动，名称/代码列固定，并显示横滑提示；整个页面不得因此出现横向溢出。展开详情、搜索和筛选均支持触控。

### 5.5 历史与方法区域

- UI-14：历史模块位于当前快照明细之后，可折叠。分别展示滚动与前瞻真实可用日期范围；至少两个有效点才绘制趋势，单个快照显示积累提示。缺失日期不补零、不跨缺口连线，不同方法版本或权重模式分段，不拼成连续序列。
- UI-15：图表包含日期轴、PE单位、TTM/FY1图例和可读取的点位详情；非正盈利的N/M不是数值点。不得预置无依据的高估/低估分区或买卖建议。
- UI-16：方法区提供公式、TTM/FY1及会计口径、代理权重处理、缺失处理、数据来源链接和方法版本。数据质量原因提供从指标或状态提示直达详情的入口。

### 5.6 状态与操作边界

- UI-17：首次加载使用固定高度骨架或加载提示，不显示示例值伪装真实值；无成功快照时呈现明确空状态及原因。
- UI-18：部分数据可用时保留有效模块，受影响指标显示不可用及覆盖率；更新失败时显示最后成功数据日期和失败提示，不把旧数值显示为刚更新。
- UI-19：公开站点提供日期浏览和允许范围内的导出，不暴露采集触发、文件导入或配置入口。导入及手动更新仅在本地或受保护的管理界面提供；导出遵守公开数据边界。

### 5.7 响应式与视觉要求

- UI-20：桌面内容居中，最大宽度建议1280px；页面留白16—32px。行业、成分及历史模块均占内容区整行。宽屏仍保持TTM/FY1两列对应关系。
- UI-21：以320px、390px、768px和1440px视口验收。宽度≥360px时卡片两列，低于360px时单列，阅读顺序为数量、市值、滚动收益率、前瞻收益率、滚动PE、前瞻PE。手机按钮可换行，长标题及状态提示不截断关键信息。

## 6. 更新与故障行为

以America/New_York时区及美股实际交易日历为准。目标交易日D的实际收盘后90分钟首次采集，失败在收盘后3小时、6小时重试；半日交易跟随实际提前收盘时间，夏令时由时区规则处理。休市日不生成新的交易日快照。调度器允许延迟执行，但快照必须标记实际采集时间。

新鲜度规则（项目默认验收政策，不是供应商保证）：

- 价格必须为D常规交易时段收盘价，拒绝盘后价代替；下一个交易日收盘后6小时仍无新成功快照，则将原快照标为更新逾期。
- 权重按第4节同日/滞后一日政策执行，分别展示来源日期与估算状态。
- 盈利与预测每次运行重新获取，缓存获取时间不得超过24小时。获取时间不是分析师修订时间，两者分别保存。
- TTM须为来源最新四个连续季度，最近季度结束距D不超过180自然日；超限标记过期并阻止完整主指标。
- 预测具有来源更新时间时，超过30自然日标记陈旧，不纳入完整前瞻主指标；来源不提供修订时间时记录“未知”，允许以新获取的来源现值计算，但质量状态必须为“预测新鲜度未验证”，不得标记全部正常。
- 快照含D收盘价格及采集时已知盈利，称为“收盘后估值快照”。如无法确认盈利信息在收盘前已公开，不得宣称是严格收盘时点可交易回测数据。

采集、校验、计算完成后原子发布。失败保留最后成功快照，显示数据日期、最近尝试时间及失败状态，不拼接部分新旧记录伪装完整成功。每种指标分别报告覆盖率和有效性；同一输入及方法版本重复运行保持幂等。

## 7. 非功能需求

- 可复现：保留输入、方法版本及结果；相同输入结果确定。
- 精度：内部计算不使用展示舍入值；数值比较使用明确容差。
- 可用性：桌面和手机可读，长表支持横向滚动，状态不只靠颜色表达。
- 性能建议：约100余个证券的已生成快照，在约定测试环境中首屏加载目标≤3秒；测试环境在设计阶段确定。
- 安全：数据凭证只保存在服务端或受控本地配置中，不写入仓库、日志及导出文件。
- 可运维：记录更新耗时、覆盖率和错误摘要，能够定位失败环节。

## 9. 已确定事项与交付边界

### 9.1 用户确定的约束

1. 个人研究、本地开发测试，并交付可公开访问的网站；Vercel为候选托管平台。
2. 数据预算为零；优先Yahoo Finance等免费来源、开源采集工具，不引入收费数据依赖。
3. 盈利口径交由项目确定，具体决定见3.2节。
4. 每个美股交易日收盘后更新，具体默认政策见第6节。
5. 历史范围以真实数据可得性决定，不预设十年目标。

### 9.2 免费数据接入与权重边界

- Yahoo Finance为价格、财务和FY1预测的首选候选，yfinance为候选开源客户端。开源软件许可证不等于底层金融数据开放许可。
- 成分和权重优先验证免费可取得的官方指数数据。Invesco官方QQQ完整持仓为备选代理来源；不得使用仅前十大持仓计算完整组合。
- 如采用QQQ代理，页面和导出必须标为“纳指100估值估算（QQQ股票持仓代理）”，不能标为官方指数PE。排除现金等非股票资产后，对完整股票集合归一化，披露排除权重与归一化系数。这是定义代理投资组合，不是第3.3节允许的舍入修正。
- 指数模式和代理模式使用独立方法版本及历史序列，不静默切换。无法获得合格完整权重时不发布完整PE，不购买数据补齐。
- 实测必须覆盖完整名单，记录每字段成功率、有效权重覆盖率、负盈利支持、FY1期间与会计口径、日期、限流及访问条件。能查到文档不等于全量数据已通过验收。

### 9.3 历史边界

从首个合格快照开始持续归档。仅在历史成分、历史权重、当时可得盈利/预测及价格均可追溯时回填对应真实历史序列。滚动与前瞻可有不同起始日；页面分别显示可用区间及缺口。

不得将当前权重或当前预测套入历史价格后标为真实历史估值；若未来增加此类情景分析，必须另命名并与历史序列隔离。缺乏历史预测时不回填前瞻历史，不以零值填缺口，不在不足样本时展示十年百分位。

### 9.4 公开部署边界

公开网站是目标交付，而非本次文档更新立即执行的部署动作。采集与网页服务解耦，网站读取已生成快照，不因每次访客访问触发全量上游抓取。具体免费调度、存储和托管组合在技术设计阶段验证，不假设Vercel免费层能承担所有采集任务。
