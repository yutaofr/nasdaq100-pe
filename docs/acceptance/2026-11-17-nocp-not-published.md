# 11 月 16 日无法更新的排查（2026-11-17）

状态：采集器已修复；2026-11-16 的真实数据仍未更新，未导入、未发布，当前发布不变。

## 证据（2026-11-17 00:07 UTC，即美东 11-16 19:07）

- 用 curl 以采集器相同的 URL 与请求头单次请求 AAPL：HTTP 200，`nocpTable` 最新一行是 11/13/2026，没有 11/16。Nasdaq 当时尚未发布 11-16 的 NOCP。
- 18 秒后用采集器的 urllib 以相同 URL 与请求头请求 AAPL、DASH 各一次：均为 Akamai `Access Denied`（HTTP 403）。此后没有再请求。两次结果各只有一个样本，不能区分“按客户端拒绝”和“短时限流”。
- 本机只有 `effectiveDate` 2026-11-15（营业日 2026-11-13）的持仓文件，没有 11-16 的持仓。
- `research-2026-11-16/refresh-attempt.json` 记录：第一次采集因索引目录不存在，全部请求完成后写索引失败；重跑时第一只证券即 403。

## 根因

1. 来源尚未发布 11-16 的收盘价和持仓，这一天当时无论是否被拒都无法更新。
2. `collect_nocp.py` 在全部请求完成后才写索引，且不创建索引目录：目录缺失时约 101 次请求的结果全部丢失，随后的重跑被拒。
3. 目标日未发布时采集器仍逐只请求全部证券，结果只显示每只 `DATE_NOT_IN_RESPONSE`，与 403 混在一起，看上去像访问被拒。

## 修改

- 发起请求前创建索引目录。
- 响应正常但最新交易日早于目标日时，记 `TARGET_DATE_NOT_PUBLISHED_YET` 和 `latest_date`，在第一只证券后停止。
- `refresh_real.py` 对此给出“尚未发布”的说明，与 403 的说明分开。
- 没有更换 HTTP 客户端，也没有改请求头：403 仍按“被拒即停”处理。
